# WP-08-08 — Financial Report Drilldowns and Exports

## Objective

Create consistent drilldown, print, CSV, and PDF-ready behavior across all Phase 8 reports.

## Read First

- AGENTS.md
- docs/phases/PHASE-08-FINANCIAL-REPORTING.md
- docs/work-packages/WP-08-07-management-profitability-reports.md

## Scope

Standardize:

- Report parameter display
- Account-level drilldown
- Journal-level drilldown
- Source-document links
- Print layouts
- CSV exports
- PDF-ready generation using the project’s approved reporting tool
- Filename conventions
- Export timestamps
- User attribution
- Confidential-report watermark or label, when configured

## Functional Requirements

- Drilldowns must preserve report filters.
- Exported totals must match onscreen totals.
- Source links must respect permissions.
- Sensitive dimensions must remain hidden without permission.
- Large exports must use memory-safe processing.
- Export generation must not mutate financial data.
- Printed and exported reports must display business name, report name, period, basis, generated time, and generated by.
- Do not expose internal database IDs unnecessarily.

## Permissions

- financial-reports.export
- financial-reports.print
- financial-reports.drilldown
- financial-reports.view-source

## Tests

- Drilldown filter preservation
- Export total reconciliation
- Permission enforcement
- Large-data handling
- Filename conventions
- No data mutation
- Required report metadata

## Acceptance Criteria

1. Drilldowns preserve report context.
2. Exports reconcile to screen totals.
3. Permissions protect sensitive data and sources.
4. Outputs include required report metadata.
5. Tests pass.

## General Requirements

- Follow `AGENTS.md`.
- Use Laravel 13, Blade, Form Requests, policies, services/actions, and focused Pest tests.
- Use posted journal entries as the accounting source of truth.
- Use decimal-safe calculations.
- Support as-of dates, date ranges, and fiscal-period filters.
- Preserve report reproducibility through explicit parameters.
- Do not hard-code BIR tax rules into financial reports.
- Do not implement BIR return filing, payroll, fixed-asset depreciation schedules, or multi-company consolidation.
- Do not modify unrelated modules.

## Completion Report

Report only:

1. Files changed
2. Commands and tests run
3. Acceptance criteria result
4. Remaining issues requiring owner action
